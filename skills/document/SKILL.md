name: document
description: use when analysis is finished and needs writing up audit-ready — finding memos, position papers, workpaper narratives — for a reader who was not in the room and will not see the working session.

# document

Announce at start: "Using document to write <deliverable> for <audience>."

<HARD-GATE>
the plan — what memo, for what audience, from which sources — is posted, in
writing, as its own message, before any source file is opened or read; a plan
narrated into the final report only after the deliverable already exists is
not a plan, however it's introduced. every factual sentence names the source
file it came from — a sentence with no possible citation is opinion, and must
say so, never stated in the same flat voice as a sourced fact.
</HARD-GATE>

1. structure: headline finding first (one sentence a reviewer could quote),
   naming every source file it draws from inline — not just in a header
   block above it — then basis, then detail, then limitations. the reader
   gets the point, and its citation, in the first three lines.
2. every factual sentence cites its source file (and section/line/cell). a
   sentence with no possible citation is opinion — label it as such or cut
   it. one sources line at the top of the memo is not a citation for every
   sentence below it.
3. distinguish, explicitly, four epistemic states and never blend them: what
   the sources say / what we computed from them / what we assume / what we
   could not verify. applying an outside framework (an accounting standard,
   a legal rule, a policy) to the sourced facts produces the second kind, an
   inference — say so; never state its conclusion in the same voice as a
   sourced fact.
4. quantify or bracket every finding (amount, range, or "unquantifiable
   because <missing source>"). name the missing document that would close
   each open item.
5. end with three separate things, none folded into another: assumptions
   (what was taken as given, and why), open items (what's still unresolved,
   with a named document that would close it), and a prepared-by /
   sources-examined block so the memo is reperformable.

## rationalizations

| excuse | reality |
|---|---|
| "the reader wants a narrative, not footnotes" | a red-transcript agent's sourcing was one line — "Pending Litigation Summary (outside counsel); Unaudited Balance Sheet, 12/31/2025 (data room)" — stated once at the top, never repeated per sentence below it. every sentence must survive "says who?" on its own. |
| "the standard/rule is just correct, it doesn't need a citation" | a red-transcript agent wrote that a company's non-accrual "is not a GAAP-compliant outcome under any reading of the facts as presented" — an outside framework's conclusion, stated as flat fact with no source file behind it and no label marking it as the preparer's own analysis. |
| "i'll cover the plan/assumptions in the closing summary" | a red-transcript agent's first text content anywhere in the run was "## What I produced" — appearing only after the deliverable had already been built and delivered. the plan is posted before the work, not narrated after. |
| "a one-line disclaimer at the end covers the assumptions" | a red-transcript agent's only nod to assumptions was one closing sentence — "Prepared for internal deal team use based solely on the two data room documents identified above; not a legal opinion." — naming no specific assumption and no prepared-by block. an open-items list is not an assumptions section. |
